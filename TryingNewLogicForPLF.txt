## NEW REQUIREMENTS ANALYSIS
The new business logic requires implementation of:
1. R200 monthly contributions with due dates
2. Catch-up fees for new members joining after July 2018
3. 7% late fees applied on the 8th of each month
4. Variable savings interest rates (configurable by admins)
5. 20% standard loan interest with 40% penalty after 90 days
6. New database tables: contributions, member_balances, financial_years, system_settings, audit_logs
7. Scheduled functions for daily/monthly processing

## STATUS UPDATE - DECEMBER 2, 2025 ✅
**Dashboard Fund Statistics Issue Identified and Fixed**: Fixed `SupabaseMemberService.calculateFundStatisticsFromMembers()` to correctly calculate total fund value from members table

**Issue**: Regular member (lesego@plf.com) was seeing R 0.00 on dashboard while superuser (oratile@tyriie.co.za) saw correct value (R 4,986,838.63)

**Root Cause**: The `calculateFundStatisticsFromMembers()` method was trying to access non-existent columns (`unpaid_contributions`, `penalties`) and falling back to default statistics

**Fix Applied**: Updated the method to:
1. Use `financial_info.current_balance` or `financial_info.savings_balance` or `financial_info.total_contributions` as fallbacks
2. Calculate outstanding amount from `catch_up_fee` + `financial_info.outstanding_amount`
3. Remove references to non-existent columns

**Verification**: 
- ✅ Anonymous user test shows R 4,986,838.63 (correct)
- ✅ Logic works when tested directly
- ✅ Issue is likely caching/compilation issue in React Native app
